# 前端设计规范

## 1. 设计目标

界面定位为企业内部运维和配置平台：信息密度适中、状态识别快速、链路关系清晰。视觉上避免过度装饰，强调可扫描的表格、可靠感和长期使用舒适度。

## 2. 信息架构

一级导航固定为：

1. 运行总览：调用量、成功率、失败数、响应时间、系统健康和最近调用。
2. 接口管理：开放路径、调用链路、成功率、启停和测试。
3. 数据源管理：数据库类型、地址、连接状态、连接池和测试。
4. 调用日志：Trace ID、接口、调用方、目标系统、状态码和耗时。
5. 系统设置：平台参数、调用凭证、权限和监控设置。

## 3. 视觉系统

- 主导航：深海军蓝 `#081426`，表达稳定和基础设施属性。
- 主操作：科技蓝 `#2768E8`。
- 成功：青绿色 `#20A67A`。
- 警告：琥珀色系；失败：红色系。
- 页面背景：冷灰 `#F3F6FA`；内容面板使用白色和细边框。
- 圆角以 7–11px 为主，避免卡片过度圆润。
- 中文使用系统无衬线字体；编码、路径、Trace ID 使用等宽字体。

## 4. 交互规则

- 列表筛选即时生效；服务端分页接入后保留筛选条件。
- 危险操作必须二次确认，并明确影响的接口和调用方。
- 状态同时使用颜色、圆点和文字，不只依赖颜色。
- 接口测试结果必须显示请求目标、状态码、耗时和 Trace ID。
- 密码和 Secret 默认不可见，保存后不允许再次读取明文。
- 调用日志详情使用侧边抽屉，避免丢失列表筛选上下文。

## 5. 响应式要求

- 1366px 及以上是主要工作宽度。
- 920px 以下导航改为抽屉。
- 680px 以下统计卡片、数据源卡片和表单改为单列。
- 表格在窄屏允许横向滚动，不挤压关键字段。
