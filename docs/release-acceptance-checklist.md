# 一期发布验收清单

> 使用人：产品、开发、测试、运维共同签字。每项填写日期、环境、执行人、Trace ID/构建号和结果；“未执行”不得写为通过。

## A. 构建与部署

- [ ] 在 Java 17 环境执行 `./scripts/build.ps1` 成功。
- [ ] 后端测试全部通过；失败项已修复或经产品书面降级。
- [ ] 前端 TypeScript 检查与生产构建通过（使用项目要求的 Node 版本）。
- [ ] 单 JAR 含前端静态资源，可通过 `./scripts/start.ps1` 启动。
- [ ] Flyway 在空库与升级库均可执行；未修改已发布的 V1、V2、V3。
- [ ] Git 不含 `target/`、`node_modules/`、`dist/`、`logs/`、`data/`、本地配置和任何密钥。

## B. 身份与后台

- [ ] 空用户表且设置 `PLATFORM_ADMIN_PASSWORD` 时，首位 ADMIN 创建成功。
- [ ] 未设置该变量时不创建默认账号且不泄露密码。
- [ ] 登录接口、`/api/auth/me`、改密、退出、Token 过期和 Token 失效逐项验证。
- [ ] ADMIN、OPERATOR、VIEWER 的接口权限与实际需求一致；特别验证 VIEWER 改密/退出的修复结果。
- [ ] 用户新增、启停、角色变更、重置密码、最后一个 ADMIN 保护均已验证。

## C. 配置与管理端契约

- [ ] 系统 CRUD 可用，`baseUrl` 校验符合预期。
- [ ] HTTP 接口 CRUD、启停、在线测试可用；不匹配目标系统协议/主机/端口的目标地址被拒绝。
- [ ] 数据源凭证不在列表/详情/API/日志中明文出现；连接测试与启停可用。
- [ ] SQL API CRUD、启停、命名参数、最大行数、超时和在线测试可用。
- [ ] 调用方页面与后端的 `code`、`permissions`、`data.client`、`data.appSecret` 契约一致。
- [ ] 创建与轮换时 Secret 仅显示一次，列表与日志无法恢复。

## D. 开放调用与安全

- [ ] 使用 `scripts/call-open-api.ps1` 成功调用一个 HTTP 路由，记录 Trace ID。
- [ ] 使用同一脚本成功调用一个 SQL 路由，记录 Trace ID。
- [ ] 使用含 Query 的请求验证规范串第三行与实际 URL 完全一致，未排序、未重编码。
- [ ] 缺少签名头、未知/停用 AppKey、过期时间戳、错误签名、重复 Nonce、未授权资源逐项被拒绝。
- [ ] Secret 轮换后旧 Secret 立即失效、新 Secret 生效。
- [ ] HTTP 转发未自动跟随重定向，报文上限与连接/读取超时按配置工作。
- [ ] 原始 SQL、非只读 SQL、多语句或不合法 SQL 参数不会被外部调用方执行。

## E. 日志与真实联调

- [ ] 每次成功、鉴权失败、路由失败、目标失败、超时、SQL 失败均可通过 Trace ID 查询。
- [ ] 请求头、请求体、响应头、响应体摘要已脱敏和截断；抽查无 JWT、密码、AppSecret、完整签名。
- [ ] 完成至少一个 WMS → 平台 → SAP 的真实 HTTP 联调。
- [ ] 完成至少一个真实业务数据源的 SQL API 联调。
- [ ] 记录目标接口、环境、测试人、日期、Trace ID 和遗留问题，形成发布结论。
