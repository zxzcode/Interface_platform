# 轻量接口平台一期产品规格

> 文档状态：可开发、可测试  
> 适用版本：一期  
> 部署形态：Java 17 + Spring Boot 4.1 模块化单体，Vue 3 管理端与后端合并为单 JAR  
> 路径约定：管理端 `/api/**`，开放接口 `/open-api/**`，健康检查 `/actuator/**`

## 1. 产品目标

一期建设企业内部轻量接口平台，统一承接 WMS、SAP、MES 等系统间的 HTTP 调用和受控 SQL 查询。平台负责接口配置、统一入口、调用方鉴权、接口授权、请求执行和完整调用日志，不替代业务系统自身的业务接口开发。

一期上线后必须形成以下闭环：

1. 管理员登录平台并维护用户、系统档案和数据源。
2. 管理员配置并发布 HTTP 转发接口或只读 SQL API。
3. 管理员创建调用方，安全地发放 AppKey、AppSecret，并授予具体接口权限。
4. 调用方按统一 HMAC-SHA256 协议访问 `/open-api/**`。
5. 平台完成身份校验、防重放、接口鉴权、目标限制、转发或查询，并返回 Trace ID。
6. 运维人员可按 Trace ID 查看成功、业务失败、平台失败和鉴权失败的完整脱敏日志。

## 2. 一期范围

### 2.1 范围内

- 后台账号密码登录、退出、修改本人密码和获取当前用户。
- 用户新增、编辑、启停、重置密码和基础角色控制。
- 系统档案 CRUD，维护系统编码、名称、基础地址和启停状态。
- HTTP 接口定义 CRUD、发布/停用、在线测试和透明转发。
- 多数据源配置、连接测试、启停和加密凭证存储。
- 只读 SQL API CRUD、命名参数、在线测试、发布/停用、行数和超时限制。
- 调用方 CRUD、AppKey、AppSecret 生成/轮换、启停。
- 按调用方授权具体 HTTP 接口和 SQL API；默认无权限。
- 开放接口 HMAC-SHA256 签名、时间窗口校验和 Nonce 防重放。
- HTTP 目标系统白名单约束，阻止接口配置形成 SSRF。
- Trace ID 全链路贯穿、请求响应摘要脱敏和调用日志查询。
- 调用指南页面，提供签名规则、请求示例和错误码说明。
- Vue 管理端与 Spring Boot 后端合并为一个 JAR，一键构建和启动。

### 2.2 范围外

- 参数拖拽映射、复杂数据转换、可视化流程编排。
- MQ 消息总线、定时同步、自动重试、补偿和分布式事务。
- Spring Cloud 微服务拆分、高可用集群和独立网关部署。
- 完整审计中心、配置审批流、租户隔离和数据权限体系。
- OAuth2、OIDC、单点登录、LDAP/AD 和第三方身份源。
- 开放接口限流计费、配额套餐和开发者门户。
- SQL 写入、DDL、存储过程和调用方提交原始 SQL。
- SAP HANA 驱动适配、日志归档自动化和配置备份自动化。

## 3. 用户与角色

后台用户与外部调用方是两类独立身份：后台用户登录管理端，外部调用方只能使用 AppKey/AppSecret 调用已授权的开放接口，不能登录管理端。

| 查看仪表盘 | 允许 | 允许 | 允许 |
| 查看系统、接口、数据源、SQL API | 允许 | 允许 | 允许 |
| 新增、编辑、启停系统档案 | 允许 | 允许 | 不允许 |
| 新增、编辑、启停 HTTP 接口 | 允许 | 允许 | 不允许 |
| 在线测试 HTTP 接口 | 允许 | 允许 | 不允许 |
| 新增、编辑、启停数据源及连接测试 | 允许 | 允许 | 不允许 |
| 新增、编辑、启停 SQL API 及在线测试 | 允许 | 允许 | 不允许 |
| 查看调用日志和日志详情 | 允许 | 允许 | 允许 |

| 查看调用指南 | 允许 | 允许 | 允许 |

补充规则：

- 所有 `/api/**` 默认要求登录，只有 `/api/auth/login` 允许匿名访问。
- 后端必须执行角色校验，前端隐藏按钮不能作为权限控制手段。
- 用户角色一期只允许单角色；角色或账号状态变化后，旧登录令牌立即失效。
- VIEWER 对管理资源只读，不允许测试接口，因为测试会产生真实外部调用或数据库查询。
- ADMIN 不允许停用自己的当前账号；系统至少保留一个已启用 ADMIN。

## 4. 后台登录与用户管理

### 4.1 登录逻辑

后台采用账号密码 + Bearer JWT：

1. 用户提交用户名和密码到 `POST /api/auth/login`。
2. 平台校验账号存在、已启用、未临时锁定，并使用 BCrypt 校验密码。
3. 登录成功返回短期 JWT、有效期和用户信息；前端将令牌保存在会话级存储，关闭浏览器后不保留。
4. 后续请求携带 `Authorization: Bearer <token>`。
5. JWT 至少包含用户 ID、用户名、角色、令牌版本、签发时间、过期时间和唯一 `jti`，不得包含密码等敏感信息。
6. 用户修改密码、被重置密码、角色变化或被停用时，增加令牌版本，使已签发令牌失效。
7. 一期不提供 Refresh Token；默认登录有效期 2 小时，过期后重新登录。
8. 用户退出时前端清除令牌；服务端提供 `POST /api/auth/logout`，使当前用户已签发的旧版本令牌失效。

后台认证与开放接口 HMAC 鉴权互不替代：JWT 不得用于 `/open-api/**`，AppKey 也不得访问 `/api/**`。

### 4.2 初始管理员

- 数据库为空时，只允许通过本地忽略配置或环境变量提供初始管理员用户名和初始密码。
- 生产环境不得在源码、Flyway、日志或 Git 中保存默认明文密码。
- 首次登录必须修改初始密码；修改完成前只能访问本人信息、修改密码和退出接口。
- 如果数据库中没有用户且未提供初始管理员配置，应用应拒绝以不安全状态启动，并输出不包含密码的配置提示。

### 4.3 密码和登录保护

- 密码长度 10～64 位，至少包含大写字母、小写字母、数字、特殊字符中的三类。
- 密码只保存 BCrypt 哈希，推荐强度参数 12；任何查询接口不得返回密码哈希。
- 同一账号连续 5 次失败后锁定 15 分钟；成功登录后清零失败计数。
- 登录失败统一提示“用户名或密码错误”，避免暴露账号是否存在；账号停用和临时锁定可在身份校验成功后给出明确提示。
- 登录接口不记录密码，请求日志不得记录 `Authorization`、Token 或完整登录请求体。

### 4.4 管理 API

| 方法 | 路径 | 用途 | 权限 |
|---|---|---|---|
| POST | `/api/auth/login` | 登录 | 匿名 |
| POST | `/api/auth/logout` | 退出并失效旧令牌 | 已登录 |
| GET | `/api/auth/me` | 当前用户、角色和是否需改密 | 已登录 |
| PUT | `/api/auth/password` | 修改本人密码 | 已登录 |
| GET | `/api/users` | 用户列表 | ADMIN |
| POST | `/api/users` | 新增用户 | ADMIN |
| PUT | `/api/users/{id}` | 编辑姓名和角色 | ADMIN |
| PATCH | `/api/users/{id}/enabled` | 启停用户 | ADMIN |
| POST | `/api/users/{id}/reset-password` | 设置临时密码并要求下次修改 | ADMIN |

一期不做用户物理删除，以保留调用日志中的操作人关联。

## 5. 系统档案管理

系统档案描述 WMS、SAP、MES、OA、SRM 等调用来源或目标系统。

### 5.1 字段

| 字段 | 规则 |
|---|---|
| systemCode | 必填、唯一、1～40 位大写字母/数字/下划线，创建后不可修改 |
| systemName | 必填，1～100 位 |
| baseUrl | 作为 HTTP 目标白名单根地址；目标系统必填，只允许 `http` 或 `https` |
| enabled | 是否允许被新配置和运行时调用 |
| healthStatus | `UNKNOWN/ONLINE/DEGRADED/OFFLINE`，一期可由连接测试或人工状态维护 |

### 5.2 业务规则

- 管理 API 为 `GET/POST /api/systems`、`GET/PUT/DELETE /api/systems/{id}`、`PATCH /api/systems/{id}/enabled`。
- 被 HTTP 接口引用的系统不得删除；停用目标系统后，引用它的开放接口运行时应拒绝调用。
- HTTP 接口的 `targetUrl` 必须与目标系统 `baseUrl` 的协议、主机和端口一致，并位于其路径范围内。
- `baseUrl` 和 `targetUrl` 不允许用户信息、URL 片段、本地文件协议或自动重定向。
- 修改 `baseUrl` 后，若已有接口地址不再符合白名单，系统档案不得直接保存，必须先调整或停用相关接口。

## 6. 调用方与接口授权

### 6.1 调用方字段

| 字段 | 规则 |
|---|---|
| clientCode | 必填、唯一、1～80 位大写字母/数字/下划线，创建后不可修改 |
| clientName | 必填，1～160 位 |
| appKey | 平台随机生成的公开标识，唯一，至少 24 个随机字符 |
| appSecret | 平台随机生成，至少 32 字节随机值；只在创建或轮换成功后显示一次 |
| enabled | 停用后立即拒绝该调用方的所有开放接口请求 |

AppSecret 必须使用项目统一的 AES-256-GCM 能力加密入库，不得明文入库、写日志、提交 Git 或在列表/详情接口中返回。平台无法展示旧 Secret；遗失后只能轮换。

### 6.2 权限模型

- 权限粒度为“调用方 + 路由类型 + 路由编码”。
- 路由类型只允许 `HTTP` 和 `SQL`；路由编码分别引用 `interfaceCode` 和 `apiCode`。
- 新建调用方默认没有任何权限。
- 接口必须同时满足“调用方启用、接口已启用、拥有明确权限”才可执行。
- 禁止使用通配符授权；一期由 ADMIN 在调用方详情页勾选具体接口。
- 接口被删除后同步删除其授权关系；接口被停用时保留授权关系，但运行时拒绝执行。

### 6.3 管理 API

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/clients` | 查询调用方列表，不返回 Secret |
| POST | `/api/clients` | 创建调用方，只在本次响应返回 AppKey 和 AppSecret |
| GET | `/api/clients/{id}` | 查询调用方详情和已授权接口，不返回 Secret |
| PUT | `/api/clients/{id}` | 修改名称 |
| PATCH | `/api/clients/{id}/enabled` | 启停调用方 |
| POST | `/api/clients/{id}/rotate-secret` | 轮换 Secret，只在本次响应返回新 Secret，旧 Secret立即失效 |
| GET | `/api/clients/{id}/permissions` | 查询已授权 HTTP 和 SQL 接口 |
| PUT | `/api/clients/{id}/permissions` | 全量保存接口授权 |

上述接口只允许 ADMIN。创建和轮换响应页面必须提示“Secret 仅显示一次”，支持一次性复制，但不能再次查看。

## 7. 开放接口 HMAC-SHA256 协议

### 7.1 请求头

```text
X-App-Key: 调用方 AppKey
X-Timestamp: Unix 毫秒时间戳
X-Nonce: 一次性随机字符串
X-Signature: HMAC-SHA256 签名
X-Trace-Id: 可选链路标识
```

规则：

- `X-Timestamp` 使用 UTC Unix 毫秒时间戳，只接受服务器当前时间前后 5 分钟内的请求。
- `X-Nonce` 为 16～64 位大小写字母、数字、短横线或下划线；同一 AppKey 下 10 分钟内不得重复。
- `X-Trace-Id` 可选，允许 8～64 位字母、数字、短横线或下划线；缺失或不合法时平台生成新值。
- `X-Signature` 为 HMAC-SHA256 结果的小写十六进制字符串。
- AppSecret 仅作为 HMAC 密钥，不随请求传输。

### 7.2 规范串

签名原文必须严格按以下顺序拼接，每一项之间使用一个换行符 `\n`，末尾不追加换行：

```text
UPPERCASE_HTTP_METHOD
CANONICAL_PATH
CANONICAL_QUERY
X_TIMESTAMP
X_NONCE
LOWERCASE_HEX_SHA256_OF_BODY
```

即：

```text
METHOD + "\n" + PATH + "\n" + QUERY + "\n" + TIMESTAMP + "\n" + NONCE + "\n" + BODY_SHA256
```

规范化规则：

1. `METHOD`：HTTP 方法转为大写，例如 `POST`。
2. `PATH`：使用实际请求路径，例如 `/open-api/material/query`；不包含域名、端口和查询串，不进行二次 URL 解码。
3. `QUERY`：无查询参数时为空字符串；有参数时使用 UTF-8 和 RFC 3986 百分号编码，按编码后的参数名升序、再按参数值升序排列，重复参数逐项保留，使用 `&` 连接为 `name=value`。
4. `TIMESTAMP`、`NONCE`：与请求头原值完全一致。
5. `BODY_SHA256`：对实际发送的原始请求体字节计算 SHA-256，再转为小写十六进制；空请求体也必须计算摘要。
6. 调用方使用 AppSecret 对完整规范串执行 HMAC-SHA256，结果转为小写十六进制后写入 `X-Signature`。

示例请求：

```text
POST /open-api/material/query?plant=1000 HTTP/1.1
Content-Type: application/json
X-App-Key: 7f80...省略
X-Timestamp: 1786330800000
X-Nonce: c267d413-5f55-44d4
X-Signature: <64位小写十六进制>

{"materialCode":"MAT-001"}
```

对应规范串结构：

```text
POST
/open-api/material/query
plant=1000
1786330800000
c267d413-5f55-44d4
<请求体SHA-256小写十六进制>
```

### 7.3 服务端校验顺序

1. 生成或接收 Trace ID，并立即写入响应头 `X-Trace-Id`。
2. 校验必填鉴权头格式。
3. 根据 AppKey 查找调用方并校验启用状态。
4. 校验时间窗口。
5. 原子登记 AppKey + Nonce；已存在则判定重放并拒绝。
6. 使用解密后的 AppSecret 重算签名，并使用恒定时间方式比较。
7. 根据请求方法和路径解析已发布的 HTTP 接口或 SQL API。
8. 校验调用方是否拥有该路由编码权限。
9. 执行 HTTP 转发或只读 SQL 查询。
10. 记录脱敏日志并返回结果；Nonce 无论后续执行成功与否均不得再次使用。

鉴权、路由和权限校验必须发生在访问目标系统或业务数据源之前。签名验证失败时不得向调用方透露签名原文、预期签名或 AppSecret。

## 8. HTTP 转发和 SQL API 行为

### 8.1 HTTP 转发

- 调用入口为管理员配置的 `/open-api/**` 路径和 HTTP 方法。
- Query、允许的 Header 和 Body 按既有契约透明转发；过滤 `Host`、`Content-Length`、连接级 Header 和平台鉴权 Header。
- 不自动跟随目标重定向；默认最大请求/响应体 1 MiB。
- 使用接口配置的连接超时和读取超时。
- 目标系统业务响应状态、响应头和响应体按既有契约返回；平台只增加 `X-Trace-Id`。
- 管理端在线测试通过受保护的 `/api/interfaces/{id}/test` 执行，调用人记为 `PLATFORM-CONSOLE`，不要求测试人员持有 AppSecret。

### 8.2 SQL API

- 调用方只提交业务参数，永远不能提交 SQL 文本、数据源信息或最大行数覆盖值。
- SQL 模板只能由 ADMIN 或 OPERATOR 配置，且仅允许单条 `SELECT` 或项目明确支持的只读语句。
- 参数使用命名参数预编译绑定，不允许字符串拼接。
- 数据源必须使用只读账号，连接池设置为只读并限制连接数。
- 单接口最大 5000 行、最大 60 秒；默认 1000 行、10 秒，管理员只能配置更严格或等于平台上限的值。
- GET 请求从 Query 获取参数，POST 请求只接受 JSON 对象；缺少参数或类型不合法时拒绝执行。
- 返回 `traceId`、`rowCount`、`maxRows` 和 `rows`，结果字段按平台脱敏规则处理。

## 9. 响应与错误码

### 9.1 管理 API

管理 API 沿用统一 `ApiResponse<T>`：

```json
{
  "success": true,
  "data": {},
  "message": "success",
  "timestamp": "2026-08-10T03:00:00Z"
}
```

### 9.2 开放接口

- 目标系统已经返回响应时，平台保留目标系统业务响应，不包装为 `ApiResponse`。
- 平台在鉴权、路由、权限、转发或 SQL 执行阶段失败时，返回统一 JSON，并始终携带 `X-Trace-Id` 响应头。

```json
{
  "success": false,
  "code": "IP-AUTH-006",
  "message": "无权调用该接口",
  "traceId": "01J...",
  "timestamp": "2026-08-10T03:00:00Z"
}
```

| HTTP 状态 | 错误码 | 含义 |
|---:|---|---|
| 400 | `IP-AUTH-001` | 鉴权请求头缺失或格式错误 |
| 401 | `IP-AUTH-002` | AppKey 不存在或调用方已停用 |
| 401 | `IP-AUTH-003` | 时间戳无效或超出允许窗口 |
| 409 | `IP-AUTH-004` | Nonce 已使用，疑似重放请求 |
| 401 | `IP-AUTH-005` | 签名不一致 |
| 403 | `IP-AUTH-006` | 调用方没有该接口权限 |
| 404 | `IP-ROUTE-001` | 请求方法和路径未匹配已发布接口 |
| 400 | `IP-REQUEST-001` | 请求体超过平台限制或请求格式不合法 |
| 403 | `IP-TARGET-002` | 目标地址不符合系统白名单 |
| 502 | `IP-TARGET-003` | 目标系统连接或响应失败 |
| 504 | `IP-TIMEOUT-001` | 目标接口或 SQL 执行超时 |
| 400 | `IP-SQL-001` | SQL 只读校验失败 |
| 400 | `IP-SQL-002` | SQL API 参数缺失或不合法 |
| 422 | `IP-SQL-003` | SQL API 执行失败 |
| 500 | `IP-INTERNAL-001` | 平台内部异常 |

同一失败场景必须稳定返回同一错误码。对外消息不得包含堆栈、数据库连接信息、SQL 全文、AppSecret 或内部网络细节。

## 10. 调用日志

每次 `/open-api/**` 请求都必须产生一条日志，包括鉴权失败和路由失败；管理端在线测试也必须产生日志。

日志至少包含：

- Trace ID、路由类型、接口编码和接口名称。
- 调用方编码；无法识别 AppKey 时记录 `UNKNOWN`，不得记录完整 AppKey。
- 请求方法、开放路径、目标系统或数据源。
- 调用开始时间、完成时间、耗时、HTTP 状态和平台错误码。
- `SUCCESS/BUSINESS_ERROR/PLATFORM_ERROR/AUTH_FAILED` 等明确状态。
- 脱敏且限长的请求头、请求摘要、响应头、响应摘要和错误摘要。

默认脱敏字段包括 `password`、`secret`、`token`、`authorization`、`cookie`、`X-App-Key`、`X-Signature`、手机号、身份证号和银行卡号。日志中不得保存 JWT、AppSecret、完整签名、数据库密码或未脱敏的大正文。

一期日志查询支持：最近记录、Trace ID 精确查询、接口编码、调用方、状态和时间范围。日志详情展示执行阶段和错误码，便于区分鉴权、路由、目标系统、超时和 SQL 错误。

## 12. 默认安全策略

| 项目 | 一期默认值 |
|---|---|
| 后台登录令牌 | JWT Bearer，2 小时有效，无 Refresh Token |
| 密码存储 | BCrypt，推荐强度 12 |
| 登录锁定 | 连续 5 次失败，锁定 15 分钟 |
| HMAC 算法 | HMAC-SHA256，小写十六进制输出 |
| 时间戳窗口 | 服务器时间前后 5 分钟 |
| Nonce 有效记录 | 同一 AppKey 保留 10 分钟，数据库唯一约束保证原子防重放 |
| 调用方权限 | 默认无权限，逐接口显式授权，无通配符 |
| AppSecret | 至少 32 随机字节，只显示一次，AES-256-GCM 加密入库 |
| HTTP 地址限制 | 目标协议、主机、端口和路径必须符合目标系统 baseUrl |
| HTTP 重定向 | 禁止自动跟随 |
| 报文上限 | 请求体、响应体默认各 1 MiB |
| SQL 限制 | 单条只读 SQL、预编译参数、默认 1000 行/10 秒，上限 5000 行/60 秒 |
| 敏感日志 | 先脱敏再截断，认证头、Cookie、密钥和密码不落日志 |
| 健康检查 | `/actuator/**` 仅向运维网络开放，不在公网暴露详细信息 |

生产环境中的数据库密码、凭证加密密钥、JWT 签名密钥和初始管理员密码只允许通过环境变量或外部配置注入。加密密钥和 JWT 密钥必须独立，均不得使用示例固定值。

## 13. 调用流程

### 13.1 管理配置流程

1. ADMIN 登录并创建 OPERATOR、VIEWER 用户。
2. ADMIN 或 OPERATOR 创建来源系统和目标系统，配置目标系统 `baseUrl`。
3. ADMIN 或 OPERATOR 创建 HTTP 接口或数据源与 SQL API，在线测试成功后启用。
4. ADMIN 创建调用方，复制一次性 AppKey/AppSecret 并通过安全渠道交付。
5. ADMIN 给调用方勾选具体 HTTP 接口和 SQL API 权限。
6. 调用方按照调用指南生成签名并联调。
7. OPERATOR 通过 Trace ID 和调用日志排查问题。

### 13.2 开放调用流程

```text
调用方生成时间戳、Nonce、请求体摘要和签名
        ↓
请求 /open-api/**，携带 AppKey 与签名头
        ↓
平台生成 Trace ID → 校验调用方 → 时间窗口 → Nonce → 签名
        ↓
解析 HTTP/SQL 路由 → 校验逐接口权限与启用状态
        ↓
HTTP：校验目标白名单并透明转发
SQL：校验只读模板和命名参数后查询只读数据源
        ↓
记录脱敏调用日志，响应返回 X-Trace-Id
```

## 14. 一期验收标准

### 14.1 登录与用户

- 数据库为空时可通过外部配置创建初始 ADMIN，源码和数据库迁移中无默认明文密码。
- ADMIN、OPERATOR、VIEWER 均可登录、退出和修改本人密码。
- 错误密码、停用用户、锁定用户、过期令牌和旧令牌均被正确拒绝。
- 角色矩阵中每个允许和禁止项至少有一个后端权限测试，直接调用 API 不能绕过前端限制。
- ADMIN 可新增、编辑、启停和重置用户；不能停用当前账号或最后一个 ADMIN。

### 14.2 系统、HTTP 接口和目标限制

- OPERATOR 可完成系统档案 CRUD，并能配置一个 WMS → SAP HTTP 接口。
- 被引用系统无法删除；不符合目标系统 `baseUrl` 的 URL 无法保存或执行。
- 已授权调用方可通过平台调用 SAP 现有 HTTP 接口，Query、允许的 Header、Body 和业务响应保持契约一致。
- 未发布接口、方法不匹配、目标系统停用、连接失败和超时均返回稳定错误码并记录日志。

### 14.3 数据源和 SQL API

- 可配置至少两个不同业务数据源，凭证加密入库且管理接口不回显密码。
- 可配置包含命名参数的只读 SQL API，调用方只提交参数即可查询。
- 原始 SQL、非 SELECT、多语句、缺失参数、超时和超过行数限制均被拒绝或截断，并记录明确结果。
- VIEWER 不能执行连接测试、HTTP 在线测试或 SQL 在线测试。

### 14.4 调用方鉴权与授权

- 创建和轮换调用方时 AppSecret 只显示一次，列表、详情、数据库明文字段和日志中均不可恢复明文。
- 正确签名且已授权的 HTTP、SQL 请求执行成功。
- 缺少鉴权头、未知/停用 AppKey、过期时间戳、重复 Nonce、错误签名和未授权接口分别被拒绝。
- 同一 Nonce 的并发请求最多只有一个通过；旧 Secret 在轮换后立即失效。
- JWT 不能调用 `/open-api/**`，AppKey 不能访问 `/api/**`。

### 14.5 日志、前端和交付

- 每次开放调用和管理端在线测试均返回并记录同一个 Trace ID。
- 成功、业务失败、平台失败、鉴权失败均可在日志页查询，敏感字段已脱敏且正文受长度限制。
- 调用指南中的规范串和 Java/cURL 示例可用于真实接口联调。
- 1366px 下全部页面可完整操作，680px 以下可完成登录、查询、查看和基础表单操作。
- 后端测试覆盖正常路径和关键失败路径，前端通过 TypeScript 检查和生产构建。
- `scripts/build.ps1` 构建成功，最终 JAR 包含前端静态资源；一键脚本可在本地 MySQL 配置下启动。
- `target/`、`node_modules/`、`dist/`、`logs/`、`data/` 和本地密钥配置未提交 Git。

## 15. 一期完成定义

同时满足以下条件才可标记一期完成：

1. 本文“范围内”功能全部具备可操作页面和受保护的后端 API。
2. 两套鉴权链路按本文实现并通过正向、越权、过期、重放和密钥轮换测试。
3. 至少完成一个真实 WMS → 平台 → SAP HTTP 接口联调，以及一个真实只读 SQL API 联调。
4. 所有调用可通过 Trace ID 定位，日志无明文密码、Secret、Token 或签名。
5. 新数据库结构只通过新增 Flyway 迁移交付，不修改已存在的 `V1`、`V2`。
6. 单 JAR 构建、启动、登录、配置、授权、调用和查日志全流程验收通过。
